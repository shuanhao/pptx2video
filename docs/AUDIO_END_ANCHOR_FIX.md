# 影片尾端定位邊界修正

## 重現與根因

在 main 的獨立工作區，以相同 Python 3.13.2、套件及 FFmpeg 環境，可重現 `test_start_and_end_measured_independently_reflect_real_stretch` 失敗。原測試預期時長約 59.940 秒，量測約 56.930 秒；與 VTT 無關。

診斷素材：原始 PCM 與 MP3 皆 60 秒，伸縮後 PCM 約 59.948 秒，加開頭 0.3 秒後的 MP4 解碼音軌約 60.247 秒。素材沒有少掉 3 秒。

尾端以原始 MP3 的最後 8 秒作比對。匯出音訊略微縮短時，正確峰值對應的原長度視窗可能超出解碼音軌邊界；`correlate(..., mode="valid")` 要求視窗完整放入，因而排除正確峰，改選較早的假峰。診斷中允許尾端額外 10ms，即找回約 60.248 秒的終點。縮短 anchor 並非穩定解法，因此不改預設 anchor 長度或測試容差。

## 修正範圍

僅尾端定位允許補零，最多為 anchor 長度的 1%（預設 8 秒即 80ms），讓邊界附近的正確峰參與比對。僅補搜尋視窗，不複製整條長音軌；回傳終點限制在實際解碼音軌範圍內，再套用既有校正係數。起點搜尋預設不補零。

補零是比對陣列的處理，不改寫 MP3、MP4 或替使用者音訊補尾端靜音。此修正不新增伸縮搜尋或低信心匹配偵測，超出此有限邊界範圍的情況仍須另外評估。

1% 是目前採用的有限邊界餘量，不是已驗證適用所有素材的最佳值。8 秒是比對片段長度，不是整個搜尋範圍；補零不代表把字幕或量測結果直接延後 80ms。診斷中只需 10ms 即可恢復此案例，80ms 的通用適用範圍仍待更多素材驗證。

本問題已在目前 main 基線重現，但尚未追溯首次引入版本，也未確認歷史輸出受影響範圍。測試素材使用白雜訊，不能把測試中的約 3 秒誤差直接套用到真實旁白。此修正不處理既有全域校正係數的系統性偏差，也不處理 2026HRT 字幕重疊問題。

## 驗證

- 新增無需 FFmpeg 的確定性測試：原始片段尾端少 1ms 時，補零後仍找到真正起點。
- 保留原伸縮測試與原有容差，音訊定位測試 8 項通過。
- 從 main 建立的修復分支完整測試 196 項通過。此分支不含 VTT，故項目數與 VTT 分支不同；不代表音訊準備分支 Stage 6 或 2026HRT 問題完成驗收。

## 合併前待驗證

以相同的既有 MP4、原始 MP3、manifest、字幕文字與校正係數，分別執行修正前後的字幕重產流程，將結果寫到不同檔案，不覆寫已驗收作品。比較末頁起點、終點及字幕時間，並實際聆聽末頁開頭、中段、末句的同步情況；若其他頁時間有改變，也需檢查差異。

目前尚未完成此真實影片對照，不宣稱真實素材全面驗收通過。已人工確認同步的舊作品不因本測試失敗而一律重做。修復合併 main 並整合進 VTT 分支後，需重新執行該分支完整測試，再更新 VTT PR 原先的失敗紀錄。
