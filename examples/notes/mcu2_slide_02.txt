MCU 架構基礎知識
各位同仁，歡迎來到 MCU Fundamentals Training Program 第二週課程。
在第一週，我們建立了一個非常重要的基礎觀念。
我們知道 MCU 是 Embedded System 的控制核心，它負責接收外部資訊、進行運算與判斷，最後控制整個系統完成各項工作。
但是，理解 MCU 是控制核心，只是第一步。
接著，一個新的問題自然就會產生。
MCU 到底是如何完成這些工作的？
為什麼一顆小小的晶片，可以同時執行程式、儲存資料、接收感測器訊號、控制馬達，還能與其他裝置進行通訊？
它的內部到底有哪些組成？
各個功能模組又是如何彼此合作，完成整個 Embedded System 的控制任務？
這些問題，就是本週課程希望回答的重點。
因此，第二週我們將從 「MCU 是什麼？」，正式進一步深入到 「MCU 裡面有什麼？」。
這也是整個 MCU Fundamentals Training Program 的第二個重要里程碑。
如果說第一週建立的是產品層級的認識，那麼這一週，我們將開始建立真正的架構思維（Architecture Thinking）。
未來無論面對任何 MCU 廠商、任何產品系列，甚至不同的應用領域，只要理解 MCU 的基本架構，就能快速掌握系統是如何運作的。

首先請看畫面左側。
這裡列出了三個「為什麼要學習 MCU 架構」的重要原因。
第一個原因，是建立正確的心智模型。
很多人在剛開始學 MCU 時，容易把它看成一顆功能很多的 IC。
但是，真正重要的並不是記住 MCU 有哪些功能，而是理解這些功能彼此之間的關係。
例如，CPU 為什麼需要 Memory？
Peripheral 為什麼不能直接控制 CPU？
資料又是如何從感測器一路傳送到 CPU，再控制外部設備？
只有理解這些元件之間的互動方式，才能真正理解 MCU 是如何運作的。
也就是說，我們學習架構，不是在背誦元件名稱，而是在建立一張完整的系統地圖。
未來當看到任何 MCU Block Diagram，都能快速理解各個模組的角色與彼此關係。

第二個原因，是串連後續所有課程的概念。
請注意。
從本週開始，後面的每一門課，其實都是建立在 MCU 架構之上。
例如，下週我們將介紹 Memory。
如果不知道 CPU 與 Memory 如何合作，就很難理解 Flash 與 SRAM 為什麼會存在。
之後介紹 GPIO、UART、SPI、I²C、ADC、Timer、Interrupt 等各種 Peripheral 時，也都需要先理解 MCU 的整體架構。
因此，這一週可以說是整個培訓課程的重要樞紐。
只要架構觀念建立好了，後面的內容就能很自然地串聯起來。

第三個原因，是提升 FAE 的工作效率。
站在 FAE 的角度，客戶很少直接問：
「CPU 是什麼？」
更多時候，他們會提出系統層級的問題。
例如：
這顆 MCU 為什麼反應比較快？
為什麼記憶體容量不夠？
為什麼資料傳輸速度會受到限制？
為什麼增加 Peripheral 後，系統效能會下降？
這些問題，都不是單一元件可以回答的。
而是需要理解整個 MCU 架構，才能快速分析原因，協助客戶找到合適的解決方案。
所以，學習 MCU Architecture，不只是增加知識，而是提升分析系統問題的能力。

接著請看畫面中央。
這裡列出了本週七項主要學習內容。
第一，我們將認識 MCU 的核心組成元件。
了解一顆 MCU 主要由哪些功能模組所構成。
第二，介紹 CPU 的角色與工作流程。
理解 CPU 如何執行程式，以及如何完成每一條指令。
第三，認識 Flash 與 SRAM。
了解兩種記憶體各自負責什麼工作，以及為什麼兩者缺一不可。
第四，介紹 Bus 與資料傳輸。
理解 MCU 內部資料如何在不同模組之間流動。
第五，認識 Peripheral。
了解 MCU 如何透過各種周邊模組與外部世界互動。
第六，我們會把前面的知識整合起來，建立 MCU 內部資料流概念。
也就是資料如何從輸入開始，經過 CPU 處理，再控制輸出設備。
最後，我們也會介紹 Clock、Reset 與 Interrupt 的基本概念。
雖然這三個主題會在後續課程深入介紹，但從架構角度來看，它們都是 MCU 能正常運作不可或缺的重要機制。
完成這七個主題後，大家就能對 MCU 的內部架構建立完整的認識。

最後請看畫面右側。
這裡說明了本週課程與整個培訓計畫之間的關聯。
第一週，我們回答的是：
MCU 是什麼？
建立了 MCU 的角色定位，以及它在 Embedded System 中的重要性。
第二週，也就是本週，我們開始回答另一個問題：
MCU 裡面有什麼？
也就是深入了解 MCU 的內部架構。
接下來，第三週將進一步深入 Memory 與 GPIO。
第四週則開始介紹 UART、SPI、I²C、USB 等 Communication Interface。
大家可以發現。
整個課程是依照由淺入深、由外到內、再由內到外的方式逐步建立完整知識架構。
這樣的安排，可以讓大家在理解每一個功能模組時，都知道它在整個系統中的位置，而不是只學習零散的知識點。

站在 FAE 的角度，本週最大的收穫，不只是開始認識 CPU、Memory 或 Peripheral，而是開始建立架構分析的能力。
未來當客戶提供一張 System Block Diagram，或描述產品的功能需求時，FAE 應該能開始思考：
這些功能會由 MCU 的哪些模組負責？
資料會經過哪些路徑？
CPU、Memory、Bus 與 Peripheral 如何彼此協同運作？
真正優秀的 FAE，不只是知道某顆 MCU 有哪些規格，而是能從系統架構角度理解產品設計，協助客戶做出更合適的方案選擇。
而這種架構思維，正是本週課程希望建立的核心能力。

請再看畫面下方的本週重點。
第二週課程，是整個 MCU Fundamentals Training Program 從「認識 MCU」走向「理解 MCU」的重要起點。
本週我們將逐步認識 CPU、Memory、Bus、Peripheral 等核心組成，了解它們如何彼此合作，共同完成資料處理與系統控制。
希望大家記住一件事。
真正理解 MCU，不只是知道裡面有哪些元件，而是理解這些元件如何形成一個完整的系統架構。
當建立這樣的架構思維之後，未來學習 Memory、Communication Interface、Timer、Interrupt，甚至 RTOS，都能更容易掌握其設計原理，並將這些知識應用到實際的產品分析與客戶技術支援之中。
