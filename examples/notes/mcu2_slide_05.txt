MCU 內部架構總覽
上一頁，我們認識了 MCU 的主要組成元件。
包括 CPU、Flash、SRAM、Peripheral、Clock System、Interrupt Controller，以及 Power Management。
但是，各位可能會產生一個新的問題。
既然 MCU 裡面有這麼多功能模組，它們彼此之間又是如何合作的？
CPU 如何讀取 Flash 裡的程式？
又如何取得 SRAM 裡的資料？
Peripheral 收到外部訊號後，又如何送到 CPU 處理？
這些資料在 MCU 內部，到底是怎麼流動的？
答案就在今天這一頁要介紹的主題——MCU 內部架構總覽。
理解這張架構圖，不只是認識各個元件的位置，更重要的是理解它們之間如何透過 System Bus 串聯起來，共同完成整個 Embedded System 的控制任務。

首先請看畫面的左側。
這裡是 CPU。
CPU 是整個 MCU 的運算核心，也是整個系統的大腦。
它負責執行程式指令、處理資料、進行邏輯判斷，並控制整個系統的運作流程。
不過，各位要注意一件事情。
CPU 雖然負責運算，但它本身並沒有儲存程式，也沒有直接連接外部世界。
因此，CPU 必須透過其他模組協助，才能完成工作。

接著請把視線移到畫面的中央。
這裡是今天最重要的主角——System Bus。
Bus 可以把它想像成 MCU 內部的高速公路。
所有資料、位址，以及控制訊號，都必須經過 Bus 傳遞。
例如。
CPU 要讀取 Flash 裡的程式。
必須透過 Bus。
CPU 要讀取 SRAM 裡的變數。
也必須透過 Bus。
UART 收到外部資料，要交給 CPU。
同樣也是透過 Bus。
因此，Bus 並不是一個運算單元。
它的工作，是負責連接所有核心模組，讓資料能夠快速且正確地流動。
可以說。
沒有 Bus，各個模組就像彼此孤立的城市，無法互相溝通。

接著看 Bus 上方。
可以看到 Memory。
Memory 又分成兩種。
第一個是 Flash。
Flash 用來儲存程式以及長期保存的重要資料。
當 MCU 上電時。
CPU 就會透過 Bus，到 Flash 讀取程式開始執行。
第二個是 SRAM。
SRAM 則提供程式執行時所需要的工作空間。
例如：
變數。
Stack。
Buffer。
以及暫時性的計算結果。
CPU 在執行程式的過程中，會頻繁地存取 SRAM。
因此。
Flash 與 SRAM 雖然都是 Memory。
但一個負責保存程式。
一個負責提供運算空間。
兩者共同支援 CPU 完成各種控制工作。

再來請看 Bus 下方。
這裡排列了許多大家熟悉的 Peripheral。
例如：
GPIO。
Timer。
UART。
ADC。
PWM。
以及其他像 I²C、SPI、CAN 等各種通訊介面。
這些 Peripheral，就是 MCU 與外部世界互動的橋樑。
例如。
GPIO 控制 LED 或讀取按鍵。
Timer 提供時間基準。
UART 負責序列通訊。
ADC 將類比訊號轉換成數位資料。
PWM 控制馬達速度或 LED 亮度。
每一個 Peripheral 都有不同功能。
但是，它們都不是獨立工作。
而是透過 Bus 與 CPU、Memory 建立連結。
例如。
ADC 收到感測器訊號後。
會把數位資料送到 Memory。
CPU 再讀取這些資料進行分析。
分析完成後。
CPU 再透過 PWM 控制馬達輸出。
整個過程，都離不開 Bus。

接著請看畫面的右側。
這裡整理了 MCU 架構的四個重要特點。
第一個是模組化設計。
MCU 並不是把所有功能混在一起。
而是將不同功能拆分成獨立模組。
例如 CPU、Memory、Peripheral。
這樣做的好處，是容易設計、容易維護，也容易擴充。
第二個重點，是資料透過匯流排傳遞。
所有模組之間交換資料，都必須經過 System Bus。
因此，Bus 是整個 MCU 的資料傳輸中心。
第三個重點，是協同運作。
CPU、Memory 與 Peripheral 並不是各自工作。
它們彼此合作。
共同完成整個控制流程。
例如：
CPU 負責判斷。
Memory 提供資料。
Peripheral 與外界互動。
缺少任何一個模組，系統都無法正常運作。
第四個重點，是高度整合。
MCU 將 CPU、Memory、Bus 與大量 Peripheral 整合到單一晶片內。
因此，不需要像一般電腦一樣，使用許多獨立晶片。
這也是 MCU 能兼具低成本、低功耗與高可靠性的原因。

如果把整張圖重新整理成一句話。
就是：
CPU 負責思考。
Memory 提供程式與資料。
Peripheral 負責感知與控制。
System Bus 則讓所有模組彼此連接。
這四個部分共同合作，形成完整的 MCU 架構。
這也是後續所有 Embedded System 課程都會反覆出現的基本模型。

站在 FAE 的角度，這一頁最大的價值，是建立「資料流」的思考方式。
未來閱讀客戶的系統架構圖時，不應只是看到有哪些元件，而是要思考資料如何流動。
例如：
感測器的資料，透過哪一個 Peripheral 進入 MCU？
CPU 如何取得資料並完成運算？
資料存放在 Flash 還是 SRAM？
最後又透過哪一個 Peripheral 控制外部設備？
當能夠掌握這條資料流，就能更快分析系統架構、定位問題，也能更有效協助客戶完成產品設計。
這也是 FAE 從介紹元件，提升到系統分析能力的重要一步。

請再看畫面下方的重點摘要。
MCU 的核心架構主要由 CPU、Memory、System Bus 與 Peripheral 四大部分所組成。
CPU 負責執行程式與運算。
Memory 提供程式與資料儲存。
Peripheral 負責與外部世界互動。
而 System Bus 則負責連接所有模組，完成資料、位址與控制訊號的傳輸。
希望大家記住一個重要觀念。
理解 MCU，不只是知道有哪些功能模組，更要理解這些模組如何透過 System Bus 協同運作，形成完整的控制架構。
下一頁開始，我們將依照這個架構，逐一深入介紹每一個核心元件，首先從 MCU 最重要的核心——CPU 的運作方式開始。
