為什麼 MCU 需要 SRAM？
上一頁，我們介紹了 Flash。
我們知道，Flash 是 MCU 的程式倉庫，負責保存程式碼、韌體以及各種重要資料。
CPU 每次開機，都必須先從 Flash 讀取程式，才能開始執行控制任務。
但是，CPU 在真正執行程式時，並不是一直直接在 Flash 裡工作。
因為程式執行過程中，會不斷產生新的資料。
例如：
變數的數值。
感測器的輸入資料。
運算結果。
函式呼叫所需的暫存空間。
這些資料都需要一個可以快速讀寫、隨時更新的工作區域。
這個工作區域，就是 SRAM（Static Random Access Memory）。
因此，如果說 Flash 是 MCU 的「程式倉庫」。
那麼 SRAM 就是 CPU 的「工作桌」。
沒有工作桌，CPU 即使有完整的程式，也無法有效率地完成運算。

SRAM 的工作，不是保存程式。
而是提供 CPU 執行期間所需要的工作空間。
也因為如此。
SRAM 又常被稱為 Working Memory，也就是工作記憶體。

接著請看畫面左下方。
那麼，SRAM 裡到底存放哪些資料？
第一，是變數（Variables）。
程式中的各種數值。
例如：
溫度。
速度。
計數器。
使用者設定。
都需要存放在 SRAM。
CPU 才能隨時讀取與修改。

第二，是陣列與資料緩衝區（Buffers）。
例如。
UART 接收資料。
ADC 連續取樣。
影像資料。
音訊資料。
通常都需要 Buffer 暫時保存。
等待 CPU 逐步處理。
因此。
很多通訊與資料處理工作，都高度依賴 SRAM。

第三，是堆疊（Stack）。
當 CPU 呼叫函式時。
需要保存目前執行狀態。
例如：
區域變數。
返回位置。
函式參數。
這些資料，都存放在 Stack。
而 Stack 本身，就建立在 SRAM 裡。
因此。
幾乎所有 C 語言程式。
每天都在使用 SRAM。

第四，是執行中的暫存資料。
例如。
CPU 正在進行數學運算。
資料比較。
邏輯判斷。
中間產生的各種結果。
都需要先放進 SRAM。
等完成下一步運算後，再決定是否輸出。
因此。
SRAM 是 CPU 運算期間不可缺少的工作空間。

接著請看畫面中央。
這裡整理了 SRAM 的五個主要特性。
第一，是讀寫速度快。
SRAM 最大的優點，就是可以快速讀寫。
CPU 幾乎可以立即取得資料。
也可以立即更新資料。
因此。
它非常適合作為執行期間的工作空間。

第二，是揮發性（Volatile）。
這代表：
只要斷電。
SRAM 裡面的資料就會全部消失。
因此。
重新開機後。
所有變數都必須重新初始化。
所以。
SRAM 並不適合保存重要資料。

第三，是容量較小。
相較於 Flash。
SRAM 的容量通常小很多。
可能只有幾 KB。
幾十 KB。
或數百 KB。
因此。
工程師在設計程式時，也需要注意 SRAM 是否足夠。

第四，是執行期間使用。
SRAM 的存在目的。
就是支援 CPU 執行程式。
它不是長期儲存空間。
而是 CPU 工作時隨時使用的工作區域。
CPU 幾乎每一條指令，都可能存取 SRAM。

第五，是不可永久保存。
由於 SRAM 屬於揮發性記憶體。
所以它適合保存：
暫存資料。
運算結果。
Buffer。
變數。
但不適合保存：
程式。
韌體。
重要設定。
這些仍然需要交給 Flash 保存。

接著請看畫面右側。
這裡整理了 SRAM 與 Flash 的比較。
首先。
SRAM 屬於揮發性記憶體。
Flash 則屬於非揮發性記憶體。
第二。
SRAM 用來存放：
變數。
暫存資料。
運算中的資料。
Flash 則負責存放：
程式碼。
韌體。
常數資料。
第三。
SRAM 斷電後資料立即消失。
Flash 則可以永久保存。
第四。
SRAM 的讀寫速度非常快。
Flash 的讀取速度雖然也很快。
但寫入速度相對較慢。
最後。
SRAM 單位容量成本較高，因此容量通常較小。
Flash 成本較低，所以可以提供較大的儲存空間。
因此。
Flash 與 SRAM 並不是互相競爭。
而是各自負責不同工作。
Flash 保存程式。
SRAM 支援程式執行。
兩者共同合作。
才能讓 MCU 順利完成所有控制任務。

站在 FAE 的角度，理解 SRAM 的價值，在於了解系統執行時真正需要多少工作空間。
例如，客戶可能會遇到：
程式可以燒錄成功，但執行後卻異常。
大量通訊資料容易遺失。
影像或感測資料處理速度變慢。
Stack Overflow。
Buffer 不足。
這些問題，很多都不是 Flash 不夠，而是 SRAM 不足所造成。
因此，FAE 在協助客戶選擇 MCU 時，不只是確認 Flash 是否放得下程式，也要評估 SRAM 是否足以支援執行期間的資料、Buffer、Stack 以及各種演算法需求，才能避免系統在實際運作時發生問題。

請再看畫面下方的重點摘要。
SRAM 是 MCU 在程式執行期間的工作區域，負責存放變數、暫存資料、Buffer、Stack，以及各種運算結果，提供 CPU 快速且即時的資料處理能力。
由於 SRAM 屬於揮發性記憶體，因此斷電後資料會消失，它的任務不是長期保存，而是支援 CPU 高效率完成每一次運算。
希望大家記住一個重要觀念。
Flash 負責保存程式，SRAM 負責執行程式。兩者各自扮演不同角色，缺少任何一種記憶體，MCU 都無法正常完成 Embedded System 的控制工作。
