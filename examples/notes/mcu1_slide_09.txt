MCU 的核心工作模型
前一頁，我們介紹了 MCU 如何完成 Input、Process 與 Output 三個基本步驟，也知道 MCU 是整個系統的控制核心。
不過，真正的 Embedded System 並不是只執行一次 Input、Decision、Output。
而是不斷重複這個流程。
MCU 就像一位永遠不會休息的管理者，持續接收資訊、分析狀況，再控制設備運作，形成一個不間斷的控制循環。
這一頁，我們將深入了解 MCU 最重要的工作模式，也就是 Input → Decision → Output 的持續循環模型。

首先請看畫面左側。
第一個步驟是 Input，也就是輸入。
MCU 的第一件工作，就是持續從外部環境取得資訊。
這些資訊可能來自各種不同的來源。
例如：
溫度感測器，量測環境溫度。
壓力感測器，偵測壓力變化。
聲音感測器，接收語音或環境聲音。
按鍵或開關，接收使用者操作。
人體感測器，偵測是否有人靠近。
影像感測器，擷取畫面資訊。
甚至還有更多不同類型的感測元件。
請注意。
這些 Input 並不是一次性輸入。
而是隨著時間持續更新。
例如，室內溫度每一秒都可能改變；使用者可能隨時按下按鍵；人體可能突然走進房間。
因此，MCU 必須持續接收新的資訊，而不是只讀取一次。
也就是說，Input 是整個控制循環的起點。

接著請看畫面中央。
第二個步驟是 Decision，也就是判斷。
所有來自 Input 的資料，都會送到 MCU。
MCU 便開始進行分析。
畫面中可以看到，MCU 在判斷時會運用多種能力。
例如：
資料處理。
先整理收到的資訊。
條件判斷。
例如目前溫度是否高於設定值？
運算能力。
根據演算法計算下一步該如何控制。
記憶能力。
保存系統目前狀態或過去資料。
效果判斷。
確認目前控制是否達到預期目標。
以及即時反應能力。
在最短時間內完成決策。
因此，Decision 並不是單純回答「是」或「不是」。
而是綜合各種資訊後，決定最適合的控制方式。
例如，同樣是溫度過高，不同產品可能採取不同策略。
有些會開啟風扇。
有些會降低馬達速度。
有些則可能直接發出警報。
真正的決策內容，取決於產品的設計需求。
這也是 MCU 最重要的工作之一。

接著來到第三個步驟。
Output，也就是輸出。
當 MCU 完成判斷後，就會開始控制外部設備。
畫面中列出了幾種常見的控制對象。
例如：
控制馬達或風扇。
開啟 LED 或燈光。
啟動蜂鳴器或喇叭。
更新顯示器畫面。
控制繼電器或電子開關。
甚至控制更多不同類型的執行器。
請注意。
Output 並不是最後一步。
很多人以為控制完成，工作就結束了。
其實不是。
控制完成後，環境可能又會改變。
例如風扇開始運轉後，室內溫度會逐漸下降。
門鎖打開後，使用者可能又再次關門。
燈光打開後，環境亮度也會改變。
因此，MCU 又會重新開始下一輪 Input。
重新收集新的資訊。
重新做判斷。
重新控制設備。
這就是畫面中所強調的：
重複循環，不斷監控與控制系統。
這也是所有 Embedded System 最重要的特色。

接著請看畫面下方。
這裡利用智慧照明系統，示範整個控制循環。
假設現在已經到了晚上。
第一步。
光線感測器偵測到環境變暗。
這就是 Input。
第二步。
MCU 收到光線感測器資料。
接著判斷：
目前環境亮度是否低於設定值？
如果答案是「是」。
那麼就決定開燈。
這就是 Decision。
第三步。
MCU 控制燈光打開。
完成 Output。
但是故事還沒有結束。
燈光打開後。
環境亮度提高。
光線感測器再次回報新的亮度。
MCU 又重新開始下一輪判斷。
如果天亮了。
亮度已經足夠。
MCU 又會決定關燈。
因此，一套智慧照明系統，不是只執行一次判斷。
而是一天二十四小時持續重複這個循環。
這就是所謂的控制迴路。
也是 MCU 在真實產品中的工作模式。

接著請看畫面右側。
這裡整理了 MCU 能夠成為控制核心的五項重要價值。
第一，是整合能力。
MCU 能夠把感測、資料處理與控制整合在同一個系統中，讓各個元件協同運作，而不是各自獨立工作。
第二，是即時性。
當環境發生變化時，MCU 能快速完成判斷並立即控制設備，確保系統穩定、安全且符合使用需求。
第三，是高效能與低功耗。
MCU 並不是一直全速運算，而是在需要時快速處理，不需要時降低耗電，因此能兼顧效能與能源效率。
第四，是可靠性。
由於 MCU 持續監控系統狀態，因此能長時間穩定運作，符合工業、家電與車用產品對可靠性的要求。
第五，是可程式化。
產品功能並不是固定的。
只要修改程式，MCU 就能改變控制邏輯，因應不同產品需求。
因此，同一套硬體平台，可以開發出許多不同功能的產品。

站在 FAE 的角度，希望各位開始養成一種分析產品的方法。
當客戶介紹產品時，可以先不要急著研究規格。
而是先試著把整個系統拆解成三個問題。
第一。
產品有哪些 Input？
有哪些感測器、按鍵或外部資訊需要收集？
第二。
MCU 需要做哪些 Decision？
哪些條件需要判斷？
有哪些控制邏輯？
第三。
最後有哪些 Output？
需要控制哪些執行元件？
只要能清楚回答這三個問題，就能快速理解產品的整體控制流程。
這種思考方式，也是後續學習 MCU 架構、Peripheral，以及 Embedded System 設計的重要基礎。

請再看畫面下方的重點摘要。
今天我們了解，MCU 並不是只執行一次控制，而是持續重複 Input → Decision → Output 的循環。透過不斷接收資訊、分析狀況，再控制外部設備，形成持續運作的控制迴路，使系統能隨著環境變化即時調整。
希望大家記住，MCU 的核心價值，不只是控制設備，而是建立一個持續監控、持續判斷、持續控制的閉環系統。 這種循環式工作模型，是智慧家電、工業控制、車用電子與 IoT 裝置共同採用的核心架構，也是後續學習 MCU 各項功能的重要基礎。
