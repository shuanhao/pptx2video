整合所有元素
各位同仁，前面的課程中，我們已經依序認識了 MCU 的各個核心組成。
從 CPU、Memory、System Bus，一直到 Peripheral，我們都是一個一個分開介紹。
但是，真正的 MCU 並不是這些元件各自獨立工作。
真正重要的是，它們如何彼此合作，完成整個 Embedded System 的控制任務。
因此，這一頁我們要做一件事情。
把前面學到的所有觀念全部串聯起來，看看一個控制動作，在 MCU 裡究竟是如何完成的。

首先請看畫面中央。
這裡以一個非常簡單的例子——按鍵控制 LED，說明 MCU 內部完整的資料流。
雖然只是按下一顆按鍵，再點亮一顆 LED。
但是在 MCU 裡，卻經歷了一連串資料交換與控制流程。
整個流程可以分成四個階段。
分別是 Input、Transfer、Process，以及 Output。

我們先看第一個階段。
Input，也就是輸入。
當使用者按下按鍵時，首先產生的是一個外部電氣訊號。
這個訊號並不會直接送到 CPU。
而是先由 GPIO 這個 Peripheral 偵測。
GPIO 接收到按鍵狀態後，便把這項資訊準備送入 MCU。
也就是說，Peripheral 是 MCU 與外部世界接觸的第一站。
它負責把感測器、按鍵或其他外部設備所產生的訊號，轉換成 MCU 可以處理的資訊。
因此，我們可以把 Peripheral 想成 MCU 的感官。
它負責接收外界事件，也是所有控制流程的起點。

接著進入第二個階段。
Transfer，也就是資料傳輸。
Peripheral 收到資料之後，不會自行做判斷。
它會透過 System Bus，把資料送到 CPU。
System Bus 就像 MCU 內部的高速公路。
CPU、Memory 與 Peripheral，彼此都不是直接相連。
所有資料、位址以及控制訊號，都必須經過 Bus 傳送。
因此，Bus 並不是拿來運算。
它真正的工作，是讓所有模組能夠互相交換資訊。
如果沒有 Bus，各個元件就像彼此沒有道路連接的城市。
即使功能再完整，也無法共同完成工作。

接著來到第三個階段。
Process，也就是資料處理。
現在，資料已經送到 CPU。
CPU 開始執行程式。
但是，各位要注意。
CPU 並不是憑空知道下一步要做什麼。
它需要先到 Flash 讀取程式。
再利用 SRAM 暫存運算資料。
Flash 保存的是程式內容。
SRAM 提供的是工作空間。
CPU 根據程式邏輯分析目前按鍵是否真的被按下。
是否符合點亮 LED 的條件。
完成判斷之後，再產生控制命令。
所以可以看到。
CPU 負責思考。
Flash 提供程式。
SRAM 提供執行空間。
三者同時合作，才能完成一次判斷。

完成判斷之後，就進入最後一個階段。
Output，也就是輸出。
CPU 將控制命令，再次透過 System Bus 傳送到 Peripheral。
GPIO 接收到控制命令之後，輸出 High 或 Low 電位。
最後 LED 接收到訊號，開始發光。
因此，真正控制 LED 的，不是 CPU 直接控制。
而是 CPU 下達命令。
Peripheral 負責執行。
這也是 MCU 控制架構最重要的設計概念。
CPU 做決策。
Peripheral 執行控制。
彼此分工合作。

請大家再回頭看一次整個流程。
按鍵產生事件。
GPIO 接收。
Bus 傳輸。
CPU 執行程式。
Memory 提供程式與資料。
CPU 做出判斷。
Bus 傳送控制命令。
GPIO 控制輸出。
最後 LED 點亮。
看似只是按下一個按鍵。
但實際上，MCU 內部已經完成了一次完整的資料流循環。
而且這整個流程，通常只需要幾微秒甚至更短的時間。
所以我們才會感覺 LED 幾乎是在按下按鍵的瞬間就亮起。

接著請看畫面下方左側。
這裡把剛才的流程，再濃縮成一個更高層次的架構。
外部世界。
透過 Peripheral 接收資訊。
經過 Bus 傳送。
CPU 執行程式。
Memory 提供程式與資料。
再由 Peripheral 將控制結果輸出到外部世界。
這就是 MCU 最基本的控制模型。
不論今天控制的是 LED、馬達、感測器、顯示器，甚至 Wi-Fi 模組。
本質上，都遵循相同的架構。
只是輸入裝置、輸出裝置，以及控制邏輯不同而已。

再看畫面中央下方。
這裡重新整理四大核心元件的角色。
CPU 是大腦。
負責執行程式、分析資料與做出決策。
Memory 是倉庫。
保存程式與執行資料，提供 CPU 使用。
Bus 是通道。
負責所有資料與控制訊號的交換。
Peripheral 則是橋樑。
負責與外部世界互動，接收輸入，也控制輸出。
請各位記住。
真正完成 Embedded System 控制工作的，不是任何一個單獨元件。
而是四個核心元件彼此合作，共同完成每一次控制循環。

最後請看右下角。
這裡用一個循環圖，再次整理整個控制流程。
系統先感知外部事件。
CPU 根據程式做出判斷。
Peripheral 執行控制。
最後產生控制結果。
而新的外部事件又會再次進入系統。
因此，MCU 並不是只完成一次工作。
而是不斷重複「感知、判斷、控制」的循環。
這也是所有 Embedded System 持續運作的基本模式。

站在 FAE 的角度，這一頁是非常重要的一頁。
未來當客戶介紹產品架構時，我們不能只看到某一顆 MCU。
更重要的是，要能理解整個資料流。
例如，資料從哪裡進來？
經過哪些 Peripheral？
CPU 如何取得程式？
Memory 如何提供資料？
System Bus 如何串聯所有模組？
最後又是哪些 Peripheral 控制外部設備？
當能夠用這樣的系統觀點分析產品，就能更快速理解客戶的系統架構，協助分析問題，並整合不同產品線的解決方案。

最後請看畫面下方的重點摘要。
今天最重要的觀念是：
MCU 並不是由 CPU、Memory、Bus 與 Peripheral 各自獨立工作，而是透過資料與控制訊號的不斷交換，形成完整的 Input、Transfer、Process 與 Output 控制流程。
理解這個完整的資料流，不只是理解 MCU 的運作方式，更是建立 Embedded System 系統思維的重要一步。
接下來，我們將利用最後一頁，重新整理本週建立的所有架構觀念，回顧 MCU Architecture 的核心重點，並建立後續學習各種 Peripheral 與系統設計的共同基礎。
