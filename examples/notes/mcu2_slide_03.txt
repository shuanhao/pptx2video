從產品視角到架構視角
上一頁，我們建立了這一週最重要的學習目標。
也就是從「MCU 是什麼」，進一步深入到「MCU 裡面有什麼」。
但是，在真正開始介紹 MCU 的內部架構之前，我們還需要先完成一個很重要的觀念轉換。
很多 FAE 在剛接觸 MCU 時，第一個注意的通常是品牌。
例如：
這是 Nuvoton 的 MCU。
這是 NXP 的 MCU。
這是 ST 的 MCU。
或是 Renesas 的 MCU。
接著，又會開始比較不同型號的規格、Flash 大小、工作頻率、腳位數量，以及價格。
這種思考方式並沒有錯。
因為它屬於產品視角（Product View）。
但是，如果希望真正理解 MCU 的運作原理，只停留在產品規格是不夠的。
我們還需要建立另一種思考方式。
也就是今天這一頁要介紹的——架構視角（Architecture View）。
因為，不論是哪一家廠商推出的 MCU，它們的內部其實都具有相似的核心架構。
而這也是後續所有課程共同的基礎。

首先請看畫面的左半部。
這代表的是產品視角。
不同的半導體公司，都推出了各自的 MCU 產品。
例如畫面中的 Nuvoton、NXP、ST，以及 Renesas。
每一家公司的產品定位都不同。
有些強調低功耗。
有些強調高速運算。
有些提供更多 Peripheral。
有些則主打工業控制或車用市場。
因此，在選擇 MCU 時，我們通常會比較許多產品規格。
例如：
工作頻率是多少？
Flash 有多大？
SRAM 有多少容量？
GPIO 有幾個？
支援哪些 Communication Interface？
是否具有 ADC、DAC、CAN 或 USB？
這些資訊，都是產品規格的一部分。
也是產品選型時的重要依據。
因此，站在產品視角，我們看到的是不同品牌、不同系列，以及不同規格之間的差異。

但是，現在請把視線移到畫面的右半部。
這裡代表的是架構視角。
請注意。
畫面上的品牌已經消失了。
取而代之的是四個熟悉的元件。
CPU。
Memory。
Bus。
以及 Peripheral。
這四個模組，就是絕大多數 MCU 都共同擁有的核心架構。
也就是說。
雖然不同品牌的 MCU 外觀看起來不同。
功能配置也可能不同。
但是，它們的基本運作方式其實非常相似。
CPU 負責執行程式與運算。
Memory 負責儲存程式與資料。
Bus 負責資料傳輸。
Peripheral 則負責與外部世界互動。
因此，我們真正需要理解的，不是哪一家廠商多了一個功能。
而是這四個核心元件如何彼此合作，完成整個 Embedded System 的控制工作。
這就是架構思維。

接著，再請看畫面下方的說明。
這裡有一句非常重要的結論。
核心架構相似，差異主要在於效能、記憶體容量與周邊功能配置。
這句話值得大家特別記住。
例如。
有些 MCU 使用 Cortex-M0。
有些使用 Cortex-M4。
甚至 Cortex-M33。
CPU 的效能不同。
但它們仍然都是 CPU。
Flash 容量可能從幾十 KB 到數 MB。
SRAM 大小也可能差很多。
但是，它們依然扮演相同的角色。
Peripheral 的數量與種類可能不同。
有人提供更多 UART。
有人增加 CAN、Ethernet 或 USB。
但是，本質上，它們仍然都是 Peripheral。
因此。
品牌之間真正不同的，是配置與規格。
真正相同的，是整個架構。
只要理解架構。
未來學習任何一家 MCU，都會變得容易許多。

這也是為什麼本課程不會先介紹某一家廠商的產品。
而是先介紹 MCU 的共通架構。
因為只有建立共同的架構觀念。
未來不論接觸 Nuvoton、NXP、ST、Renesas，甚至其他 MCU 廠商，都能快速理解它們的設計方式。
這也是建立跨品牌技術能力最有效的方法。

站在 FAE 的角度，這一頁最大的價值，就是開始從產品規格轉向系統架構。
未來客戶詢問某顆 MCU 是否適合他的產品時，FAE 不應只回答 Flash 多大、CPU 多快，或是有哪些 Peripheral。
更重要的是分析：
客戶真正需要哪些功能？
需要多少運算能力？
需要哪些周邊介面？
資料會如何在 CPU、Memory 與 Peripheral 之間流動？
也就是說，優秀的 FAE 不只是比較產品規格，而是先理解系統架構，再選擇最適合的 MCU。
當建立這樣的架構思維後，即使未來接觸新的 MCU 品牌，也能快速掌握其設計理念與技術特色。

請再看畫面下方的重點摘要。
本頁最重要的觀念，就是完成一次思考方式的轉換。
從產品視角，開始建立架構視角。
不同品牌的 MCU 雖然在效能、記憶體容量、周邊功能與產品定位上各有差異，但它們的核心架構幾乎都是由 CPU、Memory、Bus 與 Peripheral 所組成。
希望大家記住一件事。
未來學習 MCU，不要只記住品牌與型號，更重要的是理解它們共同的架構與運作原理。
建立這樣的架構思維，不僅能更快掌握不同 MCU 的技術特性，也能建立跨品牌的共同技術語言，為後續深入學習 CPU、Memory、Bus 與 Peripheral 奠定穩固的基礎。
