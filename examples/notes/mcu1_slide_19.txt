MCU 未來發展方向
到目前為止，我們已經完成了 Week 1 大部分的學習內容。
從認識 MCU 是什麼，到了解 MCU 在產品中的角色、系統架構，以及各種應用場景，我們已經建立了 MCU 與 Embedded System 的基本認知。
這一頁，我們不急著做最後總結，而是先將本週的重要觀念重新整理一次，確認整體知識架構，同時看看下一週將進一步學習哪些內容。

首先請看畫面左上角。
第一個重點。
MCU 是 Embedded System 的控制核心。
這一週我們反覆提到，MCU 的工作流程可以簡化為三個步驟。
Input。
Process。
Output。
也就是接收資訊、分析判斷，再控制外部設備。
MCU 串連了整個控制流程，是系統能夠正常運作的核心。

第二個重點。
MCU 不會單獨存在。
任何電子產品，都需要搭配 Sensor、Power、Connectivity、Actuator 等元件。
MCU 負責協調這些元件彼此合作。
因此，Embedded System 並不是一顆 MCU，而是一個完整的系統。
未來分析產品時，也要從系統角度思考，而不是只看單一晶片。

第三個重點。
理解 MCU、MPU 與 SoC 的定位差異。
MCU 強調控制。
MPU 強調運算。
SoC 強調高度整合。
它們並沒有誰比較好。
真正重要的是依照產品需求，選擇最適合的平台。
這也是系統設計最重要的第一步。

第四個重點。
MCU 的核心價值。
本週我們整理出 MCU 最重要的三項特性。
即時控制。
低功耗。
以及高整合、低成本。
正因為同時具備這些能力，MCU 才成為大多數 Embedded System 最重要的控制核心。

第五個重點。
MCU 存在於所有電子產業。
從工業控制、汽車電子、能源設備，到智慧家庭、醫療設備、消費性電子與物聯網。
只要產品需要感知、判斷與控制，就很可能使用 MCU。
因此，MCU 並不是某一個產品線的知識，而是一項跨領域的共同技術。

第六個重點。
FAE 為什麼需要理解 MCU？
因為 MCU 是許多產品線共同的技術語言。
理解 MCU，有助於快速掌握客戶需求。
分析系統架構。
與不同產品線的 FAE 或 RD 溝通合作。
也能從單一元件支援，逐步提升到整體系統方案分析。
這也是 MCU Fundamentals Training Program 最重要的目的之一。

接著請看畫面右下角。
這裡是下一週的學習預告。
第一週，我們回答的是：
MCU 是什麼？
第二週開始，我們將更深入 MCU 的內部世界。
包括：
CPU 如何執行程式。
Flash 與 SRAM 有什麼不同。
Bus Matrix 如何傳遞資料。
Peripheral 如何與 CPU 協同工作。
以及 MCU 完整的內部架構。
換句話說。
第一週建立的是系統觀念。
第二週則開始建立 MCU 架構的基礎知識。
這也是後續學習 GPIO、Timer、UART、ADC，以及 Interrupt 等課程的重要基礎。

站在 FAE 的角度，希望大家開始建立一個新的思考方式。
未來看到任何產品，不要先問：
「用了哪一顆 MCU？」
而是先思考：
這個系統需要感知哪些資訊？
需要完成哪些控制？
有哪些周邊元件需要協同運作？
只有理解整個系統，再回頭選擇 MCU，才能真正協助客戶完成最佳方案。
這就是系統導向思維，也是 FAE 持續提升專業能力的重要基礎。
