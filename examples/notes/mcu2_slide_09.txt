為什麼 MCU 需要 Flash？
上一頁，我們了解了 Memory 對 MCU 的重要性。
Memory 提供 CPU 執行程式、存取資料以及保存結果所需要的空間，是 MCU 正常運作不可或缺的核心元件。
不過，Memory 並不是只有一種。
在 MCU 裡，最重要的兩種記憶體，就是 Flash 與 SRAM。
很多人第一次接觸 MCU 時，只知道 Flash 可以存放程式。
但真正需要理解的是：
為什麼一定要有 Flash？
如果沒有 Flash，MCU 能不能工作？
答案是不能。
因為 CPU 每一次開機，都必須先從 Flash 取得程式，才能開始執行所有控制任務。
所以今天，我們先認識 Flash 在 MCU 中扮演的角色，以及它為什麼會成為所有 Embedded System 的基礎。

首先請看畫面左上角。
這張圖說明了 Flash 在 MCU 中的工作方式。
當 MCU 上電開機時。
CPU 第一件事情，就是到 Flash Memory 讀取程式。
這些程式包括：
系統初始化。
硬體設定。
控制流程。
以及整個產品的應用程式。
CPU 將程式一條一條讀出之後。
便開始執行各項控制工作。
而在程式執行過程中。
CPU 則會搭配 SRAM 儲存變數與暫時資料。
因此可以看到。
Flash 與 SRAM 雖然都是 Memory。
但兩者的工作完全不同。
Flash 負責保存程式。
SRAM 則負責支援程式執行。
兩者必須互相配合，才能讓 MCU 正常運作。

接著請看畫面左下方。
那麼，Flash 裡面到底可以存放哪些內容？
第一，是程式碼（Program Code）。
也就是工程師撰寫完成後編譯出的程式。
CPU 開機後，就是從這裡開始執行。

第二，是韌體（Firmware）。
Firmware 可以理解成產品真正運作的核心軟體。
例如：
洗衣機的洗程控制。
智慧門鎖的開鎖流程。
馬達控制演算法。
這些都屬於 Firmware。
它們通常都保存在 Flash 中。

第三，是設定資料（Configuration Data）。
很多產品需要保存一些固定設定。
例如：
通訊參數。
產品型號。
校正值。
使用者設定。
這些資料通常也會放在 Flash。
因此，即使重新開機，也不會遺失。

第四，是常數資料（Constant Data）。
例如：
查表資料。
校正參數。
固定字串。
圖形資源。
這些不需要經常修改的資料，也很適合存放在 Flash。
因此可以看到。
Flash 並不只是放程式。
很多產品的重要資料，也都保存在 Flash 裡。

接著請看畫面中央。
這裡整理了 Flash 的五個主要特性。
第一，是非揮發性（Non-Volatile）。
這是 Flash 最重要的特色。
即使斷電。
裡面的資料仍然會保留下來。
因此。
每次重新開機。
CPU 都能再次讀取相同的程式。
如果 Flash 無法保存資料。
那麼每次拔掉電源，程式都會消失。
產品也就無法再次啟動。
所以。
Flash 是 MCU 能夠正常開機的基礎。

第二，是容量較大。
一般而言。
Flash 的容量通常比 SRAM 大得多。
從幾十 KB。
到數 MB。
甚至更高。
因此。
它可以存放完整的程式以及大量固定資料。
這也是它適合作為程式儲存空間的重要原因。

第三，是以讀取為主。
Flash 的讀取速度相當快。
CPU 可以快速取得程式。
但是。
寫入與擦除速度則比較慢。
而且通常需要特定的操作流程。
因此。
Flash 並不適合頻繁修改資料。
這也是後面會介紹 SRAM 的原因。

第四，是可重複寫入。
雖然 Flash 主要用來儲存程式。
但是它仍然可以重新寫入。
例如。
產品進行 Firmware Update。
修正 Bug。
新增功能。
都需要重新更新 Flash 內容。
因此。
現在很多產品都支援 OTA 更新。
其實就是重新寫入 Flash。

第五，是可保護程式。
許多 MCU 都提供 Flash 保護機制。
避免重要程式被讀取、修改或複製。
這不只是保護智慧財產。
也是提高產品安全性的方式之一。

接著請看畫面右側。
這裡整理了 Flash 與 SRAM 的差異。
今天大家先建立概念即可。
首先。
Flash 的主要用途，是存放程式與重要資料。
SRAM 則是存放變數以及執行中的暫存資料。
第二。
Flash 斷電後資料仍然存在。
SRAM 則會全部消失。
第三。
Flash 容量通常較大。
SRAM 容量較小。
第四。
Flash 適合大量讀取。
SRAM 則讀寫速度都非常快。
最後。
Flash 可以重新寫入。
但寫入次數有限。
SRAM 則幾乎可以不限次數讀寫。
因此。
兩者並不是互相取代。
而是各自負責不同工作。

站在 FAE 的角度，理解 Flash，不只是知道它能存放程式。
更重要的是了解，它直接影響產品功能與後續維護能力。
例如，客戶可能會詢問：
程式是否放得下？
未來是否還能新增功能？
是否支援 Firmware Update？
是否需要保存校正資料或產品設定？
這些問題，本質上都與 Flash 有關。
因此，FAE 在協助客戶選擇 MCU 時，不只是評估 CPU 效能，也要確認 Flash 容量、更新方式以及資料保存需求，是否符合產品的生命週期規劃。

請再看畫面下方的重點摘要。
Flash 是 MCU 的程式倉庫，負責保存程式碼、韌體以及各種重要資料。
由於 Flash 屬於非揮發性記憶體，即使斷電，資料仍然可以完整保留，因此 MCU 每次開機，都能重新讀取程式並開始執行控制工作。
希望大家記住一個重要觀念。
Flash 的價值，不只是儲存容量，而是確保 MCU 能夠開機、執行程式，並支援產品長期穩定運作。它保存的是產品的核心功能，也是 Embedded System 能夠持續工作的基礎。
