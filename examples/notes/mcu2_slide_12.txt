Bus，MCU 內部的連接通道
前面幾頁，我們已經認識了 MCU 的主要組成元件。
CPU 負責運算與控制。
Flash 保存程式。
SRAM 提供工作空間。
Peripheral 則負責與外部世界互動。
這時候，可能會產生一個問題。
既然 MCU 裡面有這麼多不同的模組，它們彼此之間是如何互相溝通的？
例如，CPU 如何知道程式放在 Flash 的哪個位置？
CPU 又是如何把資料送到 UART、GPIO 或 ADC？
如果每個模組都各自獨立存在，而沒有任何連接方式，那麼整個 MCU 就無法形成一個完整的系統。
因此，在 MCU 內部，需要一套共同的連接機制，把所有核心模組串聯起來。
這套機制，就是 System Bus，也就是系統匯流排。
Bus 可以想像成 MCU 內部的交通道路。
CPU、Memory 與 Peripheral 就像城市裡不同的建築物。
只有道路把它們連接起來，資訊才能自由流動，各個模組才能彼此合作，完成系統控制工作。
這一頁，我們先建立 Bus 的基本概念，了解它的角色，以及為什麼它是 MCU 架構中不可或缺的一部分。

首先請看畫面左側。
很多人以為 Bus 就只有一條資料通道。
其實，在 MCU 裡，System Bus 包含三種不同功能的匯流排，每一種都有不同的任務。
第一種，是 Data Bus，也就是資料匯流排。
它負責傳送真正的資料內容。
例如 CPU 從 Memory 讀取資料，或將資料寫回記憶體，都是透過 Data Bus 完成。
因此，Data Bus 可以理解為負責搬運資料的通道。

第二種，是 Address Bus，也就是位址匯流排。
當 CPU 要存取資料時，首先要告訴 Memory 或 Peripheral：「我要存取哪一個位置？」
Address Bus 的工作，就是傳送這個位址資訊。
它決定資料要從哪裡讀取，或要寫入到哪裡。
可以把它想像成郵件上的地址。
沒有地址，就不知道資料應該送到哪裡。

第三種，是 Control Bus，也就是控制匯流排。
除了資料與位址之外，系統還需要一些控制訊號。
例如什麼時候開始讀取？
什麼時候開始寫入？
哪一個模組現在可以使用 Bus？
這些控制與同步訊號，就是透過 Control Bus 傳送。
因此，Control Bus 的工作，是確保所有模組按照正確的時序協同運作。

接著請看畫面中央。
這張圖說明了 System Bus 在 MCU 內部的位置。
可以看到。
CPU 位於中央。
左邊是 Memory。
右邊是 Peripheral。
它們之間，都是透過同一套 System Bus 互相連接。
這表示，CPU 並不是直接連接每一個模組。
而是透過共同的 Bus 與所有元件交換資訊。
這樣的設計，有幾個重要優點。
第一，架構更簡單。
新增 Peripheral 時，不需要重新設計 CPU 的連線，只要接到 Bus 即可。
第二，所有模組都遵循相同的溝通方式，整個系統更容易管理。
第三，也方便 MCU 持續擴充更多功能。

畫面下方提供了一個簡單的例子。
假設 CPU 想從記憶體讀取一筆資料。
首先，CPU 發出讀取要求。
接著，Address Bus 告訴記憶體要讀取哪一個位置。
記憶體找到資料之後，再透過 Data Bus 將資料送回 CPU。
最後，CPU 接收到資料，開始後續的處理工作。
這個例子並不是要深入介紹資料流，而是讓大家理解一件事情。
CPU、Memory 與 Peripheral 並不是直接互相連接，而是都透過 Bus 完成資訊交換。

再來請看畫面右側。
這裡整理了 System Bus 為什麼如此重要。
第一，是模組互連。
CPU、Memory 與 Peripheral 能夠形成完整的 MCU，就是因為有 Bus 將它們串聯起來。
沒有 Bus，每個模組就只能各自存在，無法協同工作。

第二，是資料流核心。
所有資料、位址以及控制訊號，都需要透過 Bus 傳送。
因此，Bus 是 MCU 內部所有資訊流動的共同通道。

第三，是協同運作。
CPU、Memory 與 Peripheral 必須依照相同的時序交換資訊。
Bus 提供一致的溝通方式，讓各個模組可以同步合作，完成控制任務。

第四，是架構擴充。
今天 MCU 裡可能只有 GPIO、UART、ADC。
未來也可能加入 USB、CAN、Ethernet 或更多周邊功能。
無論增加多少 Peripheral，它們都能透過同一套 Bus 與 CPU 建立連接。
因此，Bus 不只是連接元件，更讓 MCU 具備良好的擴充能力。

站在 FAE 的角度，Bus 是理解 MCU 架構的重要基礎。
未來閱讀任何 MCU Block Diagram，都會看到 CPU、Memory 與各種 Peripheral，幾乎都是透過 System Bus 串聯。
因此，看到 Bus 時，不需要急著研究它的電路細節。
更重要的是知道，它代表的是 MCU 內部的共同連接架構。
建立這個觀念之後，未來學習 DMA、AHB、APB、AXI 或多核心 MCU 時，就能更容易理解不同 Bus 架構之間的設計差異。

請再看畫面下方的重點摘要。
System Bus 是 MCU 內部的共同連接通道。
它負責串聯 CPU、Memory 與 Peripheral，讓各個核心模組能夠交換資訊、彼此協同，完成整個控制系統的運作。
請先記住今天最重要的一句話。
Bus 的角色不是負責運算，而是負責「連接」。它讓原本獨立的各個模組，形成一個完整且能協同運作的 MCU 系統。
