為什麼 MCU 必須有 Memory？
上一頁，我們了解了 CPU 是如何工作的。
CPU 會不斷重複 Fetch、Decode、Execute 的指令週期，持續執行程式並控制整個 MCU 系統。
但是，這裡就產生了一個很重要的問題。
CPU 要到哪裡取得程式？
運算需要使用的資料，又要存放在哪裡？
如果沒有地方存放程式與資料，CPU 即使再快，也無法開始工作。
因此，本頁要介紹 MCU 的另一個核心元件──Memory。
很多人第一次接觸 MCU，容易把 Memory 理解成只是「容量」。
例如，Flash 有多少 KB？SRAM 有多少 KB？
事實上，Memory 最重要的價值，不是容量大小，而是它提供 CPU 執行程式、存取資料以及保存結果所需要的空間。
可以說，沒有 Memory，就沒有辦法完成任何 MCU 的工作。

首先請看畫面左側。
CPU 在運作時，至少需要記憶體完成三件事情。
我們依序來看。

第一：指令必須有地方存放
首先，是程式指令。
大家還記得上一頁介紹的 Fetch 嗎？
CPU 每一次開始工作，都必須先取得下一條程式指令。
這些指令包括：
加法。
比較。
跳躍。
控制 GPIO。
啟動 Timer。
傳送 UART。
所有程式內容，都必須事先存放在記憶體中。
CPU 才能一條一條將它取出並執行。
如果沒有 Memory。
CPU 根本不知道下一步要做什麼。
因此，Memory 就像一本操作手冊。
CPU 每完成一個步驟，就會回到 Memory，再取得下一個工作。

第二：資料必須有地方存放
除了程式之外。
CPU 在運算時，也需要大量資料。
例如：
Sensor 的量測值。
UART 收到的資料。
目前系統的設定值。
使用者輸入的內容。
以及運算過程中的各種變數。
這些資料都需要暫時存放。
CPU 才能讀取、修改，再繼續後續的運算。
如果沒有地方保存資料。
CPU 就無法完成任何判斷。
例如。
智慧門鎖讀到指紋後。
必須先把指紋資料存起來。
才能開始比對。
智慧溫控器量測到目前室溫後。
也必須先保存數值。
才能判斷是否需要啟動冷氣。
因此。
Memory 不只是存放程式。
更負責保存所有運算需要的資料。

第三：執行結果必須被記錄
第三件事情，是保存結果。
CPU 完成運算後。
並不是所有資料都立即送出去。
很多結果需要被保存。
例如：
新的系統狀態。
最新的感測器數值。
通訊封包。
控制結果。
甚至錯誤訊息。
都可能需要先存放，再等待下一步使用。
例如。
CPU 計算完成 PWM Duty Cycle。
接下來還要交給 PWM Peripheral 輸出。
如果沒有 Memory 保存。
結果就會立刻消失。
因此。
Memory 不只是開始工作的地方。
也是保存工作成果的重要空間。

接著請看畫面中央。
這裡整理了 CPU 與 Memory 的合作流程。
第一步。
CPU 從 Memory 取得程式指令。
第二步。
CPU 執行運算。
第三步。
CPU 讀取或修改資料。
第四步。
完成運算後，再把結果寫回 Memory。
之後。
Memory 再把資料提供給 Peripheral。
或者等待下一次 CPU 使用。
因此。
CPU 並不是單獨工作。
而是持續與 Memory 不斷交換資料。
可以說。
Memory 就像 CPU 的工作平台。
沒有這個平台。
CPU 幾乎什麼事情都做不了。

再請看畫面最下方。
可以看到整個資料流程非常清楚。
程式。
先存放在 Memory。
CPU 從 Memory 擷取程式。
完成執行。
最後產生結果。
形成：
程式 → Memory → CPU → 結果
這也是所有 Embedded System 最基本的資料流程。

接著請看畫面右側。
這裡整理了四個重要觀念。
第一，是指令與資料的儲存基地。
Memory 是所有程式與資料的存放位置。
CPU 必須依靠 Memory，才能取得工作內容。

第二，是營運流程的必要環節。
Memory 讓 CPU 可以執行程式。
讀取資料。
完成運算。
並產生控制結果。
因此。
Memory 是 CPU 工作流程中不可缺少的一部分。

第三，是支援系統運作的核心。
所有程式執行。
資料交換。
系統控制。
甚至 Peripheral 的互動。
都需要 Memory 的配合。
它不是單純的儲存空間。
而是整個 MCU 運作的重要支援者。

第四，是不可或缺的基礎元件。
如果沒有 Memory。
CPU 就沒有程式可執行。
沒有資料可處理。
沒有地方保存結果。
整個 MCU 系統也就無法正常運作。
因此。
Memory 與 CPU 的關係，就像人類的大腦與記憶。
大腦負責思考。
記憶負責保存資訊。
兩者缺一不可。

站在 FAE 的角度，理解 Memory 的角色，不只是知道它是「記憶體」。
更重要的是理解，它決定了 MCU 能夠完成哪些工作。
例如，客戶詢問：
這顆 MCU 可以放得下我的程式嗎？
可以同時處理多筆 Sensor 資料嗎？
需要保存多少運算結果？
這些問題，本質上都與 Memory 有關。
因此，FAE 在分析客戶需求時，不只是關心 CPU 的效能，也要同步評估 Memory 是否足夠支援整個系統的程式與資料需求。
未來在選擇 MCU 時，CPU 與 Memory 往往都是同樣重要的考量因素。

請再看畫面下方的重點摘要。
Memory 提供 CPU 執行程式、存取資料以及保存結果所需要的空間，是 MCU 運作不可或缺的核心元件。
CPU 所有的工作，都建立在 Memory 的支援之上。
希望大家先建立一個重要觀念。
Memory 並不是單純的儲存空間，而是 CPU 完成所有控制工作的基礎。沒有 Memory，CPU 無法取得程式，也無法保存資料，更無法完成任何 Embedded System 的控制任務。
下一頁，我們將進一步介紹 MCU 中最重要的兩種記憶體──Flash 與 SRAM，了解它們各自負責什麼工作，以及為什麼 MCU 同時需要這兩種不同的 Memory。
