MCU 內部有哪些組成元件？
上一頁，我們完成了一個重要的觀念轉換。
我們了解到，不同品牌的 MCU，雖然產品規格各不相同，但內部其實都由相似的核心架構所組成。
接下來，我們就要正式走進 MCU 的內部。
看看一顆 MCU 裡面，到底有哪些重要的組成元件，以及它們各自負責什麼工作。
請各位先記住一個觀念。
MCU 並不是只有一顆 CPU。
它其實是一個完整的小型電腦，裡面包含運算、記憶、控制、時序管理以及與外界溝通等多種功能模組。
正因為這些模組彼此合作，MCU 才能完成 Embedded System 的各種控制任務。

首先請看畫面的中央。
可以看到 MCU 位於整個架構的中心。
四周圍繞著六個重要的功能模組。
這六個模組，就是 MCU 最核心的組成元件。
接下來，我們依序介紹它們的角色。

首先來看左上角的 CPU Core。
CPU 可以說是 MCU 的大腦。
它負責執行程式指令、進行資料運算，以及邏輯判斷。
當程式開始執行時，CPU 會一條一條讀取指令，並依照程式流程完成各種工作。
例如判斷按鍵是否被按下。
計算感測器數值。
控制 LED 是否點亮。
或決定馬達是否開始運轉。
因此，CPU 是整個 MCU 的運算核心。
不過，各位也要注意。
CPU 本身並不儲存程式，也不能直接與外部世界互動。
它需要其他模組共同合作。

接著看左側中間的 Flash Memory。
Flash 是程式記憶體。
它主要負責儲存程式，以及需要長期保存的重要資料。
即使系統斷電。
Flash 裡面的內容仍然會保留下來。
例如，我們燒錄進 MCU 的 Firmware，就是放在 Flash 裡。
因此，每當 MCU 開機時。
CPU 第一件事情，就是從 Flash 讀取程式開始執行。
可以把 Flash 想像成一本永久保存的說明書。
內容不會因為關機而消失。

再來看左下角的 SRAM。
SRAM 屬於資料記憶體。
它負責儲存程式執行過程中的暫時資料。
例如：
變數。
計算結果。
Stack。
Buffer。
以及函式呼叫時所需要的工作空間。
與 Flash 最大的不同在於。
SRAM 的速度非常快。
但是，只要系統斷電，裡面的資料就會全部消失。
因此。
Flash 負責保存程式。
SRAM 負責提供程式執行時的工作空間。
兩者缺一不可。

接著請看右上方的 Peripheral。
Peripheral，也就是周邊介面。
它的工作，就是讓 MCU 能夠與外部世界互動。
例如：
GPIO。
UART。
SPI。
I²C。
ADC。
PWM。
Timer。
USB。
CAN。
甚至 Ethernet。
這些都屬於 Peripheral。
可以說。
CPU 負責思考。
Peripheral 則負責感知世界、接收資料，以及控制外部設備。
沒有 Peripheral。
MCU 就無法與感測器、顯示器、通訊模組或馬達建立連接。

接著看右下角的 Clock System。
Clock，也就是時脈系統。
很多人第一次學 MCU 時，容易忽略 Clock 的重要性。
事實上。
Clock 就像整個系統共同使用的節拍器。
CPU 每執行一條指令。
Peripheral 每傳送一筆資料。
Timer 每累積一次計數。
全部都必須依照 Clock 提供的節奏同步運作。
如果沒有 Clock。
整個 MCU 就不知道什麼時候該開始工作。
也無法維持正確的時序。
因此，Clock System 是整個 MCU 穩定運作的重要基礎。
後續我們還會花一整週深入介紹 Clock 與 Timing 的設計概念。

最後請看下方中央的 Interrupt Controller。
Interrupt Controller，負責管理所有中斷事件。
當外部事件發生時。
例如：
按鍵被按下。
UART 收到資料。
Timer 到達設定時間。
Interrupt Controller 就會通知 CPU。
讓 CPU 能立即處理重要事件，而不需要一直等待或輪詢。
因此。
Interrupt Controller 大幅提升了 MCU 的即時反應能力。
在第五週，我們將完整介紹 Interrupt 的運作原理與 Event-Driven Architecture。

除了剛才介紹的六個核心模組之外。
畫面最上方還有一個容易被忽略，但同樣重要的模組。
那就是 Power Management。
Power Management 負責管理 MCU 的供電。
包括穩定電壓、低功耗模式以及不同工作狀態之間的切換。
例如。
當產品進入待機模式時。
Power Management 可以關閉部分模組，降低耗電。
等到事件發生，再快速喚醒 CPU。
因此，它也是 MCU 能夠兼顧高效能與低功耗的重要原因之一。

接著請看畫面右側。
這裡整理了這些元件存在的目的。
CPU 負責運算。
Memory 負責儲存。
Peripheral 負責與外部世界互動。
Clock 提供所有模組共同遵循的時序。
Interrupt Controller 提供即時事件管理。
Power Management 則確保整個系統穩定供電並降低功耗。
換句話說。
沒有任何一個元件可以單獨完成控制工作。
真正讓 MCU 發揮能力的，是這些模組彼此分工合作。
這也是 MCU Architecture 最重要的核心概念。

站在 FAE 的角度，這一頁最大的收穫，是開始建立「功能模組」的思考方式。
未來分析客戶需求時，不要只看到一顆 MCU。
而是思考：
客戶需要更多運算能力嗎？
Flash 是否足夠儲存程式？
SRAM 是否能支援演算法運作？
需要哪些 Peripheral 與外部設備連接？
是否需要更好的低功耗管理？
是否有大量即時事件，需要 Interrupt Controller 協助處理？
當能夠從這些核心模組分析系統需求時，就能更精準地協助客戶選擇合適的 MCU，也能更快速理解不同產品之間的差異。

請再看畫面下方的重點摘要。
MCU 並不是單一顆 CPU，而是整合了 CPU、Flash、SRAM、Peripheral、Clock System、Interrupt Controller，以及 Power Management 等多個核心功能模組。
每個模組都有不同的工作職責，彼此透過協同合作，讓 MCU 能夠執行程式、管理資料、處理事件、控制外部設備，並完成整個 Embedded System 的控制任務。
希望大家先建立一個重要觀念。
理解 MCU 的架構，不是背誦元件名稱，而是理解每一個模組的角色，以及它們如何共同合作完成系統控制。
