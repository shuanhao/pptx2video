總結
本週我們學到 MCU 的四大核心元件與它們的角色，以及資料如何在系統中流動。
各位同仁，經過這一週的課程，相信大家對 MCU 已經不再只是停留在「一顆晶片」的印象，而是開始理解它內部的整體架構，以及各個元件如何共同合作完成控制任務。
接下來，我們利用最後一頁，把本週所有重點整理成一個完整的架構觀念。

首先請看左上角的 MCU 架構總覽。
如果把整個 MCU 看成一個控制系統，可以發現所有元件都有明確的分工。
外部世界的資料，例如按鍵、感測器或其他裝置，首先透過 Peripheral 進入 MCU。
接著，資料透過 System Bus 傳送到 CPU。
CPU 再搭配 Memory 中的程式與資料，完成分析、判斷與控制。
最後，再經由 Peripheral 將控制結果輸出到 LED、馬達、顯示器或其他外部設備。
因此，一個完整的控制流程，就是：
Input → Peripheral → Bus → CPU → Memory → CPU → Bus → Peripheral → Output。
這也是本週最重要的系統觀念。

接著請看中間的 各元件角色快速回顧。
首先是 CPU。
CPU 可以說是 MCU 的大腦。
它負責執行程式、處理資料、分析狀態並做出控制決策。
不過，CPU 本身並不儲存程式，也不能直接與外部世界互動。
因此，它必須依賴其他元件共同合作。
接著是 Memory。
Memory 又分成 Flash 與 SRAM。
Flash 用來保存程式與重要資料，即使斷電內容仍然存在。
SRAM 則是在程式執行期間提供工作空間，存放變數、暫存資料與運算結果。
兩者功能不同，但缺一不可。
再來是 Bus。
Bus 是 MCU 內部所有元件的共同通道。
CPU、Memory 與 Peripheral 並不是直接相連，而是透過 Bus 傳送資料、位址與控制訊號。
沒有 Bus，各元件就無法彼此合作。
最後是 Peripheral。
Peripheral 是 MCU 與外部世界互動的橋樑。
它負責接收外部輸入、控制外部設備，以及完成各種通訊功能。
GPIO、UART、SPI、I²C、ADC、Timer 等，都屬於 Peripheral。
可以說，Peripheral 讓 MCU 真正具備感知、控制與通訊能力。

再來請看右上角的重要比較整理。
本週有兩個容易混淆的觀念，我們再次整理。
第一個，就是 Flash 與 SRAM 的差異。
Flash 保存的是程式碼與重要資料，具有非揮發性，斷電後內容仍然保留。
SRAM 則保存程式執行時的工作資料，讀寫速度快，但斷電後資料會消失。
因此，可以把 Flash 想成程式倉庫，把 SRAM 想成工作桌。
第二個，就是 Bus 的角色。
Bus 並不是資料本身，而是資料傳輸的通道。
CPU 必須透過 Bus 才能存取 Memory，也必須透過 Bus 才能控制 Peripheral。
所以，Bus 的價值在於連接，而不是運算。

接著請看左下角的 架構重點總結。
本週我們建立了四個重要觀念。
第一，MCU 是一台專門執行控制任務的小型電腦。
第二，CPU、Memory、Bus 與 Peripheral 四大核心元件缺一不可。
第三，所有控制流程都遵循資料流動的概念，從輸入、處理到輸出形成完整循環。
第四，各元件各司其職、彼此合作，才能讓 MCU 穩定完成各種 Embedded System 的控制任務。
這四個觀念，就是後續所有 MCU 課程的基礎。

最後請看畫面中央下方的 架構心智圖。
如果今天只能帶走一張圖，我希望就是這一張。
當你未來看到任何 MCU 系統，不論是智慧家電、工業控制、汽車電子，甚至物聯網裝置，都可以先問自己四個問題。
第一，外部資料是由哪個 Peripheral 收進來？
第二，CPU 根據什麼程式做判斷？
第三，Memory 提供哪些程式與資料？
第四，控制結果又透過哪個 Peripheral 輸出？
只要能回答這四個問題，就能快速理解一套 MCU 系統的大致架構。
這也是 FAE 在分析客戶系統時，非常重要的思考方式。

最後，請看右下角的 自我檢核題。
這五個問題，其實就是本週最重要的學習成果。
如果現在的你，已經能回答：
MCU 的四大核心元件有哪些？
CPU 的主要工作是什麼？
Flash 與 SRAM 有什麼差異？
Bus 在 MCU 中扮演什麼角色？
以及按下按鍵後，資料如何一路流動到 LED 點亮？
那麼代表你已經建立了 MCU Architecture 的基礎概念。

最後，再請大家記住本週最重要的一句話。
理解 MCU 架構，不是為了記住每一個硬體元件，而是建立系統思維。
當你能理解 CPU、Memory、Bus 與 Peripheral 如何彼此合作，就能看懂 Embedded System 如何完成感測、運算、控制與通訊，也能更有效分析客戶的系統架構。
下一週，我們將在這個基礎上，進一步深入 Memory 與 GPIO 的運作機制，了解這些核心元件如何在實際控制系統中發揮作用，並逐步建立完整的 MCU 系統架構觀念。
