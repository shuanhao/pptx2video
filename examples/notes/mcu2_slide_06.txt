CPU 的角色與定位
上一頁，我們已經建立了 MCU 的整體架構概念。
我們知道，一顆 MCU 並不是只有一個功能，而是由 CPU、Memory、System Bus 與 Peripheral 等多個模組共同組成。
那麼，這些模組當中，哪一個才是真正負責指揮整個系統運作的核心呢？
答案就是今天要介紹的 CPU。
很多人在談到 MCU 時，常常會直接說：「這顆 MCU 是 Cortex-M4」、「這顆 CPU 跑 120MHz」。
因此，很容易誤以為 CPU 就等於 MCU。
其實並不是。
CPU 只是 MCU 裡面最重要的一個核心模組。
它負責執行程式、處理資料與做出決策，但真正完成整個系統功能，還需要 Memory、Peripheral 與 System Bus 的配合。
所以，今天我們要了解的不只是 CPU 是什麼，而是 CPU 在 MCU 裡究竟扮演什麼角色。

首先請看畫面的左側。
這裡整理了 CPU 在 MCU 中最重要的三項工作。
第一項，就是執行指令（Execute Instructions）。
CPU 最基本的工作，就是依照程式設計者所撰寫的程式，一條一條執行指令。
例如。
讀取一個變數。
比較兩個數值。
進行加減乘除運算。
控制 GPIO 輸出。
或呼叫某個函式。
CPU 並不會自己思考要做什麼。
它完全依照程式指令，一步一步完成工作。
因此，我們常說：
CPU 是程式的執行者。

第二項工作，是處理資料（Process Data）。
CPU 在執行程式的過程中，需要不斷處理資料。
例如。
感測器量測到 32 度。
CPU 必須判斷：
這個溫度是否超過設定值？
如果超過，就開啟風扇。
如果沒有，就維持目前狀態。
又例如。
UART 收到一串資料。
CPU 必須解析內容、檢查格式，再決定下一步該如何處理。
因此。
CPU 不只是搬運資料。
更重要的是負責資料的分析、運算與處理。

第三項工作，就是做出判斷（Make Decisions）。
這也是 CPU 最重要的角色。
CPU 根據運算結果，決定系統下一步該採取什麼動作。
例如。
按鍵是否真的被按下？
LED 是否需要點亮？
馬達是否需要停止？
Wi-Fi 是否需要重新連線？
這些判斷，最後都由 CPU 完成。
因此，可以把 CPU 想像成整個系統的決策中心。
它負責將程式設計者的邏輯，真正轉換成系統行為。

接著請看畫面的中央。
這張圖完整說明了 CPU 如何與其他模組合作。
CPU 位於整個架構的中心。
左側是 Memory。
包括 Flash 與 SRAM。
Flash 儲存程式。
SRAM 儲存程式執行時的資料。
CPU 並沒有自己的程式。
它必須持續從 Flash 讀取指令。
同時，也必須不斷存取 SRAM 裡的資料。
因此，CPU 幾乎每一個動作，都需要 Memory 的配合。

再來看右側。
這裡是 Peripheral。
包括 GPIO、UART、ADC、Timer 等各種功能模組。
CPU 不會直接接觸外部世界。
它需要透過 Peripheral 才能完成控制。
例如。
GPIO 控制 LED。
ADC 讀取感測器。
UART 傳送資料。
Timer 提供時間基準。
因此。
Peripheral 可以說是 CPU 的眼睛、耳朵與雙手。
沒有 Peripheral。
CPU 就無法知道外界發生了什麼事情，也無法控制任何設備。

請再看畫面的下方。
CPU、Memory 與 Peripheral 中間，都透過 System Bus 相互連接。
Bus 就像 MCU 內部的高速公路。
CPU 每讀取一次程式。
每存取一次變數。
每控制一次 GPIO。
甚至每接收一次 UART 資料。
都必須透過 Bus 完成。
因此。
CPU 並不是直接與每一個模組相連。
而是透過 Bus，快速交換資料與控制訊號。
這也是為什麼我們上一頁會特別介紹 System Bus。
因為，它是整個 MCU 架構不可缺少的連接橋樑。

接著請看畫面最下方。
Bus 又連接到感測器、顯示器、馬達、無線模組，以及其他各種外部設備。
整個資料流程可以簡單整理成四個步驟。
第一。
外部世界產生事件。
例如感測器量測到新的數值。
第二。
Peripheral 接收資料。
第三。
CPU 經由 Bus 從 Peripheral 或 Memory 取得資料，完成運算與判斷。
第四。
CPU 再透過 Peripheral 控制 LED、馬達、顯示器或其他裝置。
也就是說。
CPU 雖然是核心。
但它真正的工作，是協調整個系統完成控制流程。
而不是單獨完成所有事情。

接著請看畫面右側。
這裡整理了 CPU 帶來的四項價值。
第一，是高效率。
CPU 可以在極短時間內執行大量指令，因此系統能快速回應外部事件。
第二，是精準控制。
CPU 根據程式邏輯分析資料，並控制 Peripheral 執行正確動作。
第三，是協同運作。
CPU 並不是獨立工作，而是持續與 Memory、Peripheral 以及 Bus 協同合作。
第四，是可靠穩定。
CPU 按照固定的程式流程執行，不受人為操作影響，因此能長時間穩定運作。
這四項能力，也是 MCU 能夠廣泛應用於工業控制、智慧家電、車用電子與醫療設備的重要原因。

站在 FAE 的角度，這一頁最重要的收穫，是建立「CPU 是協調者，而不是萬能者」的觀念。
未來分析客戶需求時，不要只關心 CPU 的速度有多快。
更重要的是思考：
CPU 是否有足夠的運算能力？
需要搭配多少 Flash 與 SRAM？
需要哪些 Peripheral 支援？
資料如何透過 System Bus 在各模組之間流動？
真正決定系統效能的，往往不是 CPU 本身，而是 CPU 是否能與 Memory、Peripheral 以及整個系統架構有效協同運作。
這也是系統設計與 MCU 選型時，FAE 必須具備的重要思考能力。

請再看畫面下方的重點摘要。
CPU 是 MCU 的控制中心，負責執行程式指令、處理資料並做出決策。
不過，CPU 並不是獨立工作，而是持續透過 System Bus 與 Memory 及 Peripheral 協同合作，才能完成整個 Embedded System 的控制流程。
希望大家記住一個重要觀念。
CPU 是 MCU 的大腦，但不是 MCU 的全部。真正讓 MCU 發揮完整功能的，是 CPU、Memory、System Bus 與 Peripheral 彼此緊密合作所形成的完整系統架構。
