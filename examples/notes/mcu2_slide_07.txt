CPU 如何運作？
上一頁，我們認識了 CPU 在 MCU 中的角色。
我們知道，CPU 是整個 MCU 的控制中心，負責執行程式、處理資料以及做出決策。
但是，CPU 到底是如何完成這些工作的呢？
它是不是像人一樣，看到事情就立即思考？
答案並不是。
CPU 的所有工作，其實都遵循一套固定且不斷重複的流程。
這套流程，就是今天要介紹的 Instruction Cycle，也就是指令週期（Instruction Cycle）。
無論是控制 LED、接收 UART 資料、量測感測器，甚至執行複雜的控制演算法，本質上都只是 CPU 一次又一次地執行相同的指令週期。
理解這個流程，不只是了解 CPU 的工作方式，更是未來學習 Memory、Peripheral、Interrupt，以及整個 Embedded System 運作機制的重要基礎。

首先請看畫面中央。
CPU 的工作可以簡化成三個步驟。
也就是：
Fetch、Decode、Execute。
請不要小看這三個步驟。
今天所有 MCU、MPU，甚至桌上型電腦與手機的 CPU，本質上都是依照這個流程持續運作。
不同的只是速度、複雜度以及架構設計。

第一個步驟：Fetch（擷取指令）
請先看左邊第一個區塊。
CPU 並不知道下一步要做什麼。
它必須先到 Flash，也就是程式記憶體中，取得下一條程式指令。
例如。
程式可能寫著：
讀取 ADC。
控制 GPIO。
傳送 UART。
或更新一個變數。
CPU 會依照程式順序，一條一條將指令取出。
這個動作，就稱為 Fetch。
因此，Fetch 可以理解成：
把下一個工作拿到 CPU 面前。
如果把 CPU 比喻成一位廚師。
Flash 就像一本食譜。
Fetch，就是翻開下一頁，看看下一道菜要做什麼。
所以。
Fetch 的重點不是執行。
而是取得下一條指令。

第二個步驟：Decode（解碼指令）
接著請看中間。
CPU 拿到指令之後。
還不能直接執行。
因為 CPU 必須先理解這條指令代表什麼意思。
例如。
這條指令是：
加法？
減法？
比較大小？
控制 GPIO？
還是讀取 UART？
CPU 需要分析指令內容。
確認需要哪些硬體資源。
需要哪些資料。
以及下一步應該完成什麼工作。
這個理解指令的過程，就稱為 Decode。
可以把它想像成廚師看到食譜之後。
先閱讀內容。
確認需要哪些材料。
以及接下來應該怎麼料理。
所以。
Decode 的目的，就是：
了解這條指令到底要做什麼。

第三個步驟：Execute（執行指令）
接著請看右邊。
當 CPU 完全理解指令之後。
就正式開始執行。
例如。
完成加法運算。
控制 LED 點亮。
啟動 Timer。
傳送 UART 資料。
或更新某一個 Peripheral 的控制暫存器。
所有真正產生結果的工作，都發生在 Execute 階段。
如果剛才的例子是廚師。
那麼 Execute 就是真正開始炒菜、煮菜。
最後完成一道料理。
因此。
Execute 的重點，就是：
真正完成工作並產生結果。

接著請注意畫面下方的箭頭。
CPU 並不是執行一次就停止。
而是在完成 Execute 之後。
立刻回到下一次 Fetch。
然後再次 Decode。
再次 Execute。
形成一個持續循環。
也就是：
Fetch → Decode → Execute → Fetch → Decode → Execute……
這個循環，一秒鐘可能重複數百萬次。
甚至數億次。
所以。
CPU 看起來像是在同時做很多事情。
其實，它只是以極快速度，不斷重複同一個工作流程。
這也是 CPU 能夠持續控制整個 MCU 系統的原因。

接著請看畫面右側。
這裡整理了 CPU 運作時的四個重要特性。
第一，是高速連續運作。
CPU 會持續執行指令週期。
根據不同 MCU 的時脈速度。
每秒可以完成數百萬，甚至上億次的指令循環。
因此。
人眼幾乎感覺不到任何延遲。
例如。
LED 即時亮起。
按鍵立即回應。
馬達快速啟動。
背後都是 CPU 高速執行指令的結果。

第二，是循序執行。
CPU 大多依照程式順序，一條一條執行指令。
也就是：
先完成前一條。
再處理下一條。
因此。
程式設計時，每一行程式的執行順序都非常重要。
後續介紹 Branch、Interrupt 等主題時，我們也會看到 CPU 如何在特殊情況下改變執行流程。

第三，是快速反應。
當外部事件發生。
例如。
按鍵被按下。
UART 收到資料。
Timer 到達時間。
CPU 可以快速開始新的指令處理流程。
配合後續要介紹的 Interrupt 機制。
MCU 就能在極短時間內完成系統回應。
這也是 MCU 能夠應用在即時控制的重要原因。

第四，是精確控制。
CPU 並不是隨機工作。
每一條指令都依照程式設計者預先定義的流程執行。
因此。
它能精確控制 Peripheral 的每一個動作。
例如。
PWM 的輸出頻率。
ADC 的取樣時間。
UART 的資料傳送。
都是 CPU 根據程式精確控制的結果。

站在 FAE 的角度，理解 CPU 指令週期最大的價值，在於建立「程式執行流程」的觀念。
未來分析客戶問題時，例如：
為什麼系統反應變慢？
為什麼某個功能沒有立即執行？
為什麼資料沒有即時更新？
很多問題，其實都與 CPU 如何執行程式有關。
例如。
CPU 是否忙於其他工作？
程式流程是否過於複雜？
是否因為等待某個 Peripheral 而造成延遲？
因此，FAE 不需要深入研究 CPU 的電路設計，但必須理解 CPU 是如何一步一步執行程式，才能更有效地分析系統行為，並協助客戶找出真正的問題來源。

請再看畫面下方的重點摘要。
CPU 並不是隨機工作，而是持續重複 Fetch、Decode、Execute 三個步驟，形成完整的指令週期。
透過這個不斷循環的流程，CPU 才能持續執行程式、處理資料，並控制整個 MCU 系統穩定運作。
希望大家記住一個重要觀念。
所有 MCU 的控制能力，都建立在 CPU 持續執行指令週期之上。理解 Fetch、Decode 與 Execute，不只是了解 CPU 的運作方式，更是後續學習 Memory、Peripheral、Interrupt，以及整個 Embedded System 架構的重要基礎。
