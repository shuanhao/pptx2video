MCU 內部構造
前面幾頁，我們已經知道 MCU 是 Embedded System 的控制核心，也了解它在各種產品中的角色與價值。
不過，大家可能會開始好奇一個問題。
MCU 為什麼能同時完成感測、運算、控制與通訊？
答案就在它的內部架構。
這一頁，我們不討論電路設計或晶片製程，而是從系統架構的角度，認識 MCU 由哪些主要模組組成，以及這些模組如何彼此合作，形成完整的控制核心。
當建立這個整體觀念後，未來學習 Memory、GPIO、Timer、UART、ADC 等周邊功能時，就能知道它們各自在 MCU 中的位置與角色。

首先請看整張圖。
畫面最左邊代表的是外部世界，也就是輸入來源。
Embedded System 並不是封閉運作的，它需要持續與外界互動。
例如。
感測器回報環境資訊。
使用者按下按鍵。
馬達回傳運轉狀態。
LED 顯示目前系統狀態。
Wi-Fi 或藍牙模組傳送資料。
這些都屬於外部世界所產生的資訊。
MCU 的第一項工作，就是接收這些外部事件。
換句話說，沒有外部輸入，MCU 就不知道系統發生了什麼事情。

接著把視線移到中央。
這就是 MCU 的內部。
首先看到的是最重要的元件──CPU。
CPU 可以理解成 MCU 的大腦。
它負責執行程式指令。
完成各種運算。
依照程式流程做出判斷。
最後決定系統下一步要執行哪些控制動作。
不過請注意。
CPU 本身並沒有儲存能力，也無法直接與外界溝通。
它必須依靠其他模組共同合作。
因此，一顆 MCU 並不是只有 CPU 而已。

CPU 的旁邊，就是記憶體系統。
記憶體主要分成兩種。
第一種是 Flash。
Flash 用來儲存程式。
可以把它想像成一本永久保存的說明書。
當產品出廠之後，韌體程式通常就存放在 Flash 裡。
即使電源關閉，內容仍然會保留下來。
因此，Flash 又稱為非揮發性記憶體。
另一種是 SRAM。
SRAM 用來存放程式執行時所需要的資料。
例如。
變數。
計算結果。
暫時性的工作資料。
當 MCU 開始執行程式時，CPU 會不斷讀寫 SRAM。
但是，只要電源關閉，SRAM 的資料就會消失。
因此，它適合存放執行期間的工作內容。
大家可以簡單記住。
Flash 放的是程式。
SRAM 放的是工作中的資料。
兩者分工合作，才能讓 CPU 順利執行程式。

再往下看。
可以看到一條連接所有模組的線路。
這就是匯流排系統（Bus Matrix）。
它可以想像成 MCU 內部的高速道路。
CPU 要讀取 Flash。
要存取 SRAM。
要控制 Timer。
要讀取 ADC。
甚至要操作 GPIO。
都需要透過匯流排進行資料交換。
因此，Bus 並不負責運算，而是負責讓所有模組彼此溝通。
如果沒有 Bus，各個模組就像一座座孤島，無法合作完成系統工作。

接著請看右上角。
這裡是電源與時脈管理。
很多人認為 MCU 只要供電就能工作。
其實並沒有那麼簡單。
首先，需要穩定的電源管理。
例如 LDO 或 DC-DC 電源電路，負責提供穩定電壓。
同時，也需要低功耗模式，在沒有工作時降低能源消耗。
另一項重要功能就是時脈。
時脈就像整個系統共同遵循的節拍器。
CPU 執行速度。
Timer 計時。
UART 通訊。
SPI 傳輸。
ADC 取樣。
幾乎所有功能，都需要時脈同步。
因此，電源與時脈管理雖然不直接參與運算，但卻是 MCU 能正常工作的基礎。

接著請看畫面下方。
這裡是 MCU 最具有特色的一部分，也就是Peripherals，周邊模組。
大家可以發現，這些名稱其實就是未來幾週課程會逐一介紹的重要內容。
例如。
GPIO，負責數位輸入與輸出。
Timer，負責計時與 PWM。
UART、SPI、I²C，負責資料通訊。
ADC，負責把類比訊號轉成數位資料。
DAC，將數位資料轉成類比輸出。
Comparator，比較不同電壓。
Interrupt Controller，負責事件即時通知。
Watchdog Timer，監控系統是否正常運作。
另外還有 USB、CAN、RTC 等其他特殊功能。
請注意。
CPU 雖然是大腦。
但是 MCU 能完成這麼多不同工作，就是因為整合了大量不同的 Peripheral。
不同產品可能搭配不同數量或不同種類的周邊模組，因此形成各式各樣的 MCU 產品系列。

最後請看最右邊。
這裡代表 MCU 與外部設備之間的介面。
例如。
Digital I/O。
Analog Input。
各種通訊介面。
電源輸入。
以及除錯介面。
這些介面就是 MCU 與外界互動的窗口。
透過這些介面。
MCU 才能真正讀取感測器資料、控制馬達、驅動顯示器，並與其他設備交換資訊。
因此，一顆 MCU 並不是單純執行程式，而是不斷透過這些介面與真實世界互動。

現在，把整張圖重新串聯一次。
外部世界產生資訊。
透過各種 I/O 傳送進 MCU。
Peripheral 負責接收或產生資料。
CPU 依照程式進行判斷。
Flash 提供程式。
SRAM 提供工作空間。
Bus 負責資料傳輸。
最後再透過各種輸出介面控制外部設備。
這就是一顆 MCU 在 Embedded System 中完整的運作流程。

站在 FAE 的角度，希望大家不要把 MCU 看成一份 Datasheet，也不要把 CPU、Memory、GPIO、UART 視為彼此獨立的功能。
真正重要的是理解它們之間如何協同工作。
例如，當客戶說按鍵沒有反應時，問題可能不是 GPIO，而可能涉及 Interrupt、時脈設定，甚至電源管理。
又或者，客戶反映通訊速度不足，除了 UART 本身之外，也可能與 CPU 負載、Bus 存取或 Memory 使用有關。
因此，FAE 在分析問題時，應該從整體架構思考，而不是只聚焦單一模組。這種系統觀點，也是後續所有 MCU 課程希望逐步建立的核心能力。

請再看畫面下方的重點摘要。
今天我們認識了 MCU 的基本內部架構，包括 CPU、Flash、SRAM、Bus Matrix、電源與時脈管理，以及各種 Peripheral 模組。這些元件彼此分工合作，共同完成資料接收、運算、控制與輸出的完整流程。
希望大家記住，MCU 並不是只有 CPU，而是一個高度整合的控制平台。 未來課程將依序介紹 GPIO、Memory、Communication Interface、Timer、ADC、Interrupt 等主題，而今天建立的這張架構圖，將成為理解後續所有內容的重要基礎。
