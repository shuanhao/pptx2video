資料如何在 MCU 裡流動？
各位同仁，前面幾頁課程中，我們已經認識了 MCU 的主要組成，包括 CPU、Memory、System Bus，以及 Peripheral。
但是，了解這些元件各自的功能，只是第一步。
真正重要的是，它們並不是各自獨立運作，而是透過資料的不斷流動，共同完成一個完整的控制流程。
因此，這一頁我們要回答一個非常重要的問題：
資料究竟是如何在 MCU 裡面流動的？
理解資料流，也就能理解 MCU 如何從接收外部資訊，到做出判斷，再控制外部設備完成工作。

首先請看畫面中央。
這張圖完整描述了 MCU 內部的資料流路徑。
整個流程可以分成四個階段：
Input，也就是輸入。
接著是 CPU 與 Memory 共同完成資料處理。
然後由 Peripheral 負責控制輸出。
最後產生 Output，驅動外部設備完成動作。
這就是 Embedded System 最基本、也是最重要的控制流程。

首先來看第一個階段，Input，也就是輸入。
所有控制都必須從取得資訊開始。
這些資訊可能來自按鍵、感測器、通訊模組，或其他外部設備。
例如：
按鍵提供使用者操作。
溫度感測器提供環境溫度。
光線感測器提供亮度資訊。
UART、SPI 或 I²C 等通訊介面，則接收其他 IC 傳來的資料。
這些資訊首先會進入 MCU 的 Peripheral。
也就是 GPIO、ADC、UART 等周邊模組。
Peripheral 的工作，就是把外部世界的訊號整理成 MCU 可以處理的資料。
可以把 Peripheral 想成資料的第一站。

接著請看中央的 CPU。
當 Peripheral 收到資料之後，CPU 就開始工作。
CPU 會從 Memory 讀取程式。
其中 Flash 保存的是程式碼。
SRAM 則保存執行期間需要使用的資料、變數與暫存內容。
CPU 依照程式內容開始分析資料。
例如：
按鍵是否被按下？
目前溫度是多少？
收到的通訊封包是否正確？
是否需要開啟警報？
這些判斷，都由 CPU 根據程式逐步完成。
因此，CPU 並不是自己知道要怎麼做，而是依照 Flash 中的程式，搭配 SRAM 中的資料，一步一步完成運算與決策。

接著請注意 CPU 與 Memory 之間的關係。
很多初學者會以為，CPU 自己保存所有資料。
其實不是。
CPU 本身幾乎不保存程式與大量資料。
它必須持續向 Memory 取得程式與資料。
所以整個流程其實是不斷重複進行：
CPU 從 Flash 讀取程式。
再從 SRAM 取得目前需要處理的資料。
完成運算後，再把新的資料寫回 SRAM。
整個過程，CPU 與 Memory 一直持續交換資訊。
這也是為什麼前面課程一直強調：
沒有 Memory，CPU 就無法正常完成任何控制工作。

接著請看下方的 Peripheral。
當 CPU 完成判斷之後，就會把控制命令交給 Peripheral。
Peripheral 再依照不同功能，把控制結果送往外部設備。
例如：
控制 GPIO 點亮 LED。
控制 PWM 調整馬達速度。
控制 DAC 輸出類比電壓。
控制 UART 傳送資料。
控制 Display 更新畫面。
可以看到，Peripheral 不只是接收輸入，也負責完成輸出控制。
它是 MCU 與外部世界互動的重要橋樑。

最後就是 Output，也就是輸出。
輸出代表控制結果真正影響外部世界。
例如：
LED 被點亮。
馬達開始旋轉。
蜂鳴器發出聲音。
七段顯示器更新數字。
或是把資料透過 USB、UART 傳送給其他設備。
這時候，CPU 的決策才真正轉換成產品的實際功能。
因此，我們可以把整個流程整理成一句話：
Input 提供資訊，CPU 負責判斷，Peripheral 完成控制，Output 則實現最終功能。

接著請看左側的兩個生活案例。
第一個案例，是按鍵控制 LED。
使用者按下按鍵之後，Button 產生輸入訊號。
GPIO 接收到按鍵狀態。
CPU 判斷按鍵是否有效。
確認之後，再控制 GPIO 點亮 LED。
整個過程雖然只有短短幾毫秒，但裡面已經完整經歷了資料流的每一個步驟。

第二個案例，是溫度感測顯示。
Temperature Sensor 持續量測環境溫度。
ADC 或其他 Peripheral 接收感測資料。
CPU 根據程式完成計算與判斷。
最後，再把結果送到 Display 顯示目前的溫度，例如畫面上的 25.6 度。
這也是智慧家電、工業設備與醫療產品中最常見的資料流模式。

從 FAE 的角度來看，理解資料流比記住單一元件更重要。
因為當客戶提出問題時，真正需要分析的是：
資料從哪裡進來？
經過哪些模組？
在哪裡完成運算？
最後又由哪一個 Peripheral 輸出控制？
只要能掌握這條資料流，就能快速判斷問題可能發生的位置，也更容易與不同產品線的 FAE 共同分析整個系統。

最後請看畫面下方的重點摘要。
無論是感測器、按鍵還是通訊資料，MCU 都遵循相同的資料流模式。
也就是：
Input → CPU → Output。
在這個過程中，Memory 提供程式與執行資料，System Bus 則負責串聯各個模組，讓資料能夠在 CPU、Memory 與 Peripheral 之間順利流動。
請記住一個核心觀念：
MCU 的價值，不只是擁有 CPU、Memory 或 Peripheral，而是在於能夠整合所有模組，讓資料持續流動，最終完成感測、運算與控制，驅動整個 Embedded System 正常運作。
